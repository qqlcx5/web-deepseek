# Cherry Studio 网页端需求文档

## 1. 项目概述

### 1.1 产品名称

Cherry Studio Web（以下简称“网页端”）。

### 1.2 建设目标

构建一个可在浏览器中使用的 Cherry Studio 网页端，聚焦多模型 AI 对话。网页端必须能够导入 Cherry Studio 桌面端导出的 `data.json`，并导出符合该结构的 `data.json`，使同一份数据可在桌面端和网页端之间迁移、继续使用。

本期不提供任何工具调用或联网能力。产品只处理本地数据、用户直接配置的模型服务和模型对话请求。

### 1.3 当前数据基线

项目根目录已有 Cherry Studio 导出文件 [`data.json`](../data.json)。文件为 UTF-8 JSON，约 20 MB，当前包含：

| 数据项 | 当前数量/特征 |
| --- | --- |
| 助手 | 默认助手 1 个，普通助手 5 个 |
| 会话 | 396 条 |
| 消息块 | 2,608 条 |
| IndexedDB 数据表 | `topics`、`message_blocks`、`settings`、`translate_history` 等 |
| 持久化配置 | 助手、模型、设置、快捷短语、插件/工具相关配置等 |

`data.json` 的顶层结构为：

```json
{
  "time": 1785929771066,
  "version": 5,
  "localStorage": {
    "persist:cherry-studio": "{...JSON 字符串...}"
  },
  "indexedDB": {
    "topics": [],
    "message_blocks": []
  }
}
```

注意：`localStorage["persist:cherry-studio"]` 本身是 JSON 字符串；其内部的大部分字段，如 `assistants`、`llm`、`settings`，也可能再次是 JSON 字符串。实现必须按层解析并按原格式序列化，不能把嵌套字符串直接改成对象。

## 2. 范围

### 2.1 本期必须交付

1. 浏览器端导入、保存、导出 `data.json`。
2. 助手管理：查看、新建、编辑、删除、排序和按标签筛选。
3. 会话管理：新建、重命名、删除、搜索、切换助手、查看历史消息。
4. 对话：流式输出、停止生成、重新生成、编辑并重新发送、复制消息。
5. 模型配置：读取、编辑并使用导入数据中的 LLM 供应商和模型配置。
6. 设置：恢复并编辑与上述功能直接相关的通用设置。
7. 数据兼容校验、失败提示和导出前完整性校验。

### 2.2 明确不做

以下能力不出现在导航、配置页、输入区或运行时请求中；导入数据中对应字段可以原样保留，以保证导出兼容性。

- MCP 服务器、Function Calling、代码执行器、插件、Mini App、输入工具。
- 联网搜索、网页抓取、URL 内容读取、引用检索、搜索结果展示。
- 知识库、文件上传、文件解析、RAG、记忆库。
- 绘图、翻译、OCR、语音输入输出、笔记。
- Cherry Studio 账号、云同步、Nutstore、Copilot、OpenClaw。

## 3. 用户与核心流程

### 3.1 目标用户

已有 Cherry Studio 桌面端数据，且希望在浏览器中继续管理助手、会话和模型对话的个人用户。

### 3.2 首次使用

1. 用户打开网页端，看到“导入 `data.json`”主操作。
2. 用户选择桌面端导出的 `data.json`。
3. 系统解析、校验并写入浏览器本地数据库。
4. 系统显示导入统计：助手数、会话数、消息数、忽略的非本期功能配置数。
5. 用户进入最近会话，或新建会话开始对话。

### 3.3 日常对话

1. 用户从侧边栏选择助手和会话，或新建会话。
2. 用户选择已配置的模型，输入文本并发送。
3. 系统向用户配置的模型 API 发起对话请求，逐段展示回复。
4. 系统将用户消息、模型回复、用量和会话更新时间写入本地数据。
5. 用户可停止、重新生成、编辑消息后重新发送，或切换至其他会话。

### 3.4 回到桌面端

1. 用户在网页端选择“导出数据”。
2. 系统先执行结构和引用完整性校验。
3. 系统生成并下载完整 `data.json`。
4. 用户在 Cherry Studio 桌面端导入该文件，继续查看助手、会话和消息。

## 4. 功能需求

### 4.1 数据导入与本地存储

- 支持从文件选择器导入单个 `.json` 文件；不从网络地址导入数据。
- 仅接受顶层包含 `time`、`version`、`localStorage`、`indexedDB` 的 Cherry Studio 导出结构。
- 解析前保留原始文件；解析、完整性校验和入库必须在浏览器本地执行。
- 导入采用事务：任一步失败不得覆盖当前可用数据。
- 导入成功后，以浏览器 IndexedDB 保存业务数据，以本地持久化存储保存界面及兼容性配置。
- 再次导入时提供“替换全部数据”和“取消”两项；本期不提供跨文件合并，避免 ID 冲突和消息归属错误。
- 不支持的字段必须进入“兼容保留区”，导出时原样带回，不能静默丢失。

### 4.2 助手管理

- 显示默认助手和普通助手，展示名称、头像/emoji、标签、系统提示词、模型设置和会话数。
- 支持新建、编辑、复制、删除普通助手；默认助手不可删除。
- 支持编辑名称、emoji、系统提示词、温度、Top P、最大输出 Token、上下文轮数、流式输出和自定义模型参数。
- 支持按导入数据的 `unifiedListOrder`、`tagsOrder`、`collapsedTags` 恢复排序和分组状态。
- 删除助手前必须二次确认，并说明其下会话的处理方式；本期将会话一并删除，避免产生桌面端无法识别的孤立会话。

### 4.3 会话与消息

- 每个会话归属一个助手，支持新建、重命名、删除、搜索和按更新时间排序。
- 加载历史会话时，按 `topics -> messages -> message_blocks` 关系还原消息。
- 支持 `user`、`assistant`、`system` 三类消息；至少正确显示文本块和 Markdown/代码内容。
- 消息应保存 `id`、`role`、`topicId`、`assistantId`、`createdAt`、`status`、`modelId`、`model`、`usage`、`traceId` 与块 ID 引用。
- 每个消息块至少保存 `id`、`messageId`、`type`、`createdAt`、`status`、`content`、`citationReferences`。本期不生成引用；现有引用字段原样保留。
- 支持复制消息内容、编辑最后一条用户消息并重新发送、重新生成最后一条助手消息、停止流式输出。
- 会话标题默认取首条用户文本的前 28 个字符；用户手动改名后必须设置 `isNameManuallyEdited: true`，后续不自动覆盖。

### 4.4 模型与对话请求

- 从持久化配置中的 `llm` 读取供应商、API 地址、密钥引用、模型列表及模型参数。
- 提供供应商和模型的查看、新建、编辑、删除及启停；敏感 API Key 在界面中脱敏显示。
- 支持 Cherry Studio 数据中已存在且网页端适配的文本对话协议，首期至少覆盖 OpenAI 兼容 Chat Completions 和 Anthropic Messages。
- 只发送完成当前文本对话所需的消息、系统提示词和模型参数；请求中不得携带工具定义、MCP 配置、联网搜索开关、文件内容或知识库上下文。
- 流式响应应实时更新当前助手消息块；中止、网络错误或模型错误必须写入明确的消息状态，不得把未完成内容标记为成功。
- 对话 API 请求是用户明确配置模型后触发的直接模型通信，不属于联网搜索功能；系统不得自行访问第三方网站或检索服务。

### 4.5 导出与兼容性

- 用户可随时导出当前完整状态为 `data.json`，文件名格式为 `cherry-studio-web-YYYYMMDD-HHmmss.json`。
- 导出前必须执行以下校验：
  - 所有助手 ID 全局唯一。
  - 所有会话引用的助手存在。
  - 所有消息引用的会话和助手存在。
  - 所有消息块的 `messageId` 存在于消息集合。
  - 每个消息 `blocks` 数组中的块 ID 均存在。
  - 嵌套序列化字段可被 `JSON.parse` 再次解析。
- 导出必须生成 `time` 为当前时间戳、保留可识别的 `version`，并保留未支持模块的原始配置字段。
- 网页端创建或编辑的数据必须使用 UUID，避免与桌面端导入数据发生 ID 冲突。

## 5. 数据映射与兼容约束

| 业务域 | `data.json` 来源 | 网页端处理 |
| --- | --- | --- |
| 助手与排序 | `persist.assistants` | 解析、编辑、保存、导出 |
| 模型供应商 | `persist.llm` | 解析、编辑、用于文本对话、导出 |
| 通用设置 | `persist.settings` | 仅映射本期支持项，其他字段保留 |
| 会话 | `indexedDB.topics` | 解析、编辑、保存、导出 |
| 消息 | `topics[].messages` | 解析、编辑、保存、导出 |
| 消息块 | `indexedDB.message_blocks` | 解析、编辑、保存、导出 |
| 不在范围的配置 | 如 `mcp`、`websearch`、`knowledge` | 不渲染、不执行、原样保留 |

实现中应建立“原始兼容数据”和“网页端业务视图”两层模型。业务视图只暴露本期能力；导出时以原始兼容数据为底稿，将网页端已编辑的助手、模型、会话和消息回写至对应字段。这样可防止一次网页端使用后删除桌面端的未实现配置。

## 7. 非功能需求

- 隐私：除用户明确发起的模型 API 调用外，网页端不得发起任何网络请求；不得上传 `data.json` 或遥测数据。
- 性能：以当前 20 MB、396 会话、2,608 消息块的数据文件为基线，现代桌面浏览器完成本地解析与首屏可交互时间不超过 5 秒；长会话消息列表需虚拟滚动或分页渲染。
- 可靠性：写入数据时使用 IndexedDB 事务；浏览器意外关闭后，已完成的消息和设置不得损坏。
- 安全：API Key 仅存于用户浏览器本地存储，导出前显示包含密钥的风险提示，并允许用户选择是否在导出文件中保留密钥。
- 可访问性：键盘可操作侧栏、会话列表和发送区；图标按钮具备可访问名称；消息状态可被屏幕阅读器识别。
- 浏览器：支持当前稳定版 Chrome、Edge、Safari、Firefox 的桌面端；移动端支持当前 iOS Safari 与 Android Chrome。

## 8. 验收标准

1. 导入当前根目录的 `data.json` 后，页面显示 6 个助手、396 个会话和 2,608 个消息块，不发生数据丢失或 JavaScript 解析错误。
2. 任意已存在会话打开后，消息顺序、用户/助手角色、文本内容和消息时间与导入数据一致。
3. 新建助手、新建会话、发送一轮模型对话后，刷新浏览器仍可看到新增内容。
4. 在网页端导出后，导出文件通过结构校验；重新导入网页端后，新增和原有的助手、会话、消息均存在。
5. 导出的文件可被目标 Cherry Studio 桌面端导入，且不产生重复助手 ID、悬空会话、悬空消息块或嵌套 JSON 解析错误。
6. 全站无 MCP、工具调用、联网搜索、网页访问、知识库、文件上传和引用检索入口；模型请求体中不包含 `tools`、`tool_choice`、`mcp`、搜索或知识库字段。
7. 在未配置模型或模型请求失败时，历史数据仍可浏览、导出和再次导入。
8. 浏览器开发者工具网络面板中，未发起对话时没有业务网络请求；发起对话时仅出现用户配置的模型 API 请求。

## 10. 待确认项

- 目标 Cherry Studio 桌面端的具体版本及其导入入口。验收前需用该版本做一次真实导入测试，因为导出字段随 Cherry Studio 版本演进。
- 模型供应商协议 支持 openai 格式 chat completions 和 claude 格式
- API Key 的导出默认策略。建议默认导出密钥，用户明确勾选后才写回 `data.json`；这会与桌面端的“完整配置迁移”便利性产生取舍。
