# Orbit Chat UI 重设计文档集

> 受众：UI/UX 设计师与设计型 AI 模型。目的：在不读代码的前提下，重新设计整个产品的界面。
> 仓库：`web-deepseek`　产品名：Orbit Chat　形态：本地优先的 Web 应用（Vite SPA，非浏览器扩展）

## 这是什么产品（一句话）

一个**本地优先**的 AI 对话 + 网页阅读 + 云备份 Web 应用：用户自配 API Key，在浏览器里和多 Provider 大模型对话；可抓取网页存入本地知识库、全文搜索、随时与当前网页对话；可用 S3 / WebDAV 备份全部数据。

## 为什么现在要重设计

当前界面是"纯对话单页"，且大量手写 DOM 没用组件库，存在三类硬伤（详见 `06-design-direction.md`）：

1. **功能已扩张，界面没跟上**：新增了"网页阅读 + 记忆库 + 云同步"，但 UI 还只有对话页，没有清晰的阅读/记忆库/同步入口。
2. **组件不一致**：输入框、消息列表、侧边栏都是手写，与已引入的 `vue-element-plus-x` 组件库（Bubble / XSender / Conversations / Welcome 等）风格割裂。
3. **流式与状态反馈缺失**：发送后看不到逐字增量、停止/失败/重生成状态不清、连接/同步状态不可见。

## 阅读建议（给设计模型）

1. 先读 `01` → `02` 建立范围认知。
2. 读 `06` 的"必须修复痛点"，避免重蹈旧设计。
3. 读 `03` 定信息架构，再按 `04` 逐屏设计。
4. 用 `05` 的令牌与组件库约束视觉；用 `07` 核对每屏数据。

## 交付物建议

- 信息架构图 + 导航方案（桌面/平板/移动三态）
- 关键屏线框 / 高保真：对话（空 + 流式 + 错误 + 停止）、阅读（抓取 + 三视图预览）、记忆库（搜索 + 列表）、设置（Provider/模型、同步/存储）
- 组件态枚举：消息状态机、抓取状态机、连接测试状态、同步状态
- 响应式断点行为说明（≥1180 / 760–1180 / ≤760）
- 暗色模式配色（令牌已提供 light/dark 两套）

## 不在本期 UI 范围（明确排除）

- RSS / 订阅源相关界面
- AI 自动化 / 定时任务 / 任务队列相关界面
- 服务端账户、多人协作、团队空间
- entity 级三方合并冲突解决 UI（同步 v1 仅快照上下传 + 回滚）
