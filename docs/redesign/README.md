# Orbit Chat UI 重设计文档集

> 受众：UI/UX 设计师与设计型 AI 模型。目的：在不读代码的前提下，重新设计整个产品的界面。
> 仓库：`web-deepseek`　产品名：Orbit Chat　形态：本地优先的 Web 应用（Vite SPA，非浏览器扩展）

## 这是什么产品（一句话）

一个**本地优先**的多 Provider AI 对话 Web 应用：用户自配 API Key，与 OpenAI 兼容 / Anthropic / Ollama 多家大模型流式对话；用 S3 / WebDAV 备份全部数据。数据存在浏览器 IndexedDB，与 Cherry Studio 数据格式互通。

## 设计基线（重要）

- **数据兼容 Cherry Studio**：运行时干净类型 + 导入导出零摩擦。不引入 Cherry 没有的实体（不做独立"文档库"）。
- **"喂内容给 AI"靠附件/粘贴**，不靠独立的网页抓取视图——这是聊天应用的天然方式。
- **备份 = Cherry 导出格式**：WebDAV/S3 备份的就是 Cherry 能读的 data.json，二合一。

## 为什么现在要重设计

当前界面是"纯对话单页"，且大量手写 DOM 没用组件库，存在三类硬伤（详见 `06-design-direction.md`）：

1. **组件不一致**：输入框、消息列表、侧边栏都是手写，与已引入的 `vue-element-plus-x` 组件库（Bubble / XSender / Conversations / Welcome 等）风格割裂。
2. **流式与状态反馈缺失**：发送后看不到逐字增量、停止/失败/重生成状态不清、连接/同步状态不可见。
3. **设置与导航散乱**：模型参数归属混乱、Provider 就绪状态不可见、移动端挤压。

## 阅读建议（给设计模型）

1. 先读 `01` → `02` 建立范围认知。
2. 读 `06` 的"必须修复痛点"，避免重蹈旧设计。
3. 读 `03` 定信息架构，再按 `04` 逐屏设计。
4. 用 `05` 的令牌与组件库约束视觉；用 `07` 核对每屏数据。

## 交付物建议

- 信息架构图 + 导航方案（桌面/平板/移动三态）
- 关键屏线框 / 高保真：对话（空 + 流式 + 错误 + 停止）、对话历史搜索、设置（Provider/模型、同步/存储）
- 组件态枚举：消息状态机、连接测试状态、同步状态
- 响应式断点行为说明（≥1180 / 760–1180 / ≤760）
- 暗色模式配色（令牌已提供 light/dark 两套）

## 明确不做（避免过度设计）

- **网页抓取 / 阅读视图 / 文档库**：浏览器扩展形态，不适合 Web 聊天应用。
- RSS / 订阅源 / Feed。
- AI 自动化 / 定时任务 / 任务队列。
- 服务端账户、多人协作、团队空间。
- entity 级三方合并冲突解决 UI（同步为快照上下传 + 回滚）。
- 把网页内容喂给 AI 用"附件/粘贴/URL 插入附件"实现，不建独立文档实体。
